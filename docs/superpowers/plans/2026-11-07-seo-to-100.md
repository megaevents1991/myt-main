# SEO to 100 Implementation Plan (mega-events.co.il)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close every finding of the 2026-11-07 claude-seo audit (53/100) without changing how the site looks or works for a customer, then re-audit.

**Architecture:** Three phases ordered by risk. Phase A touches only `<head>`, the sitemap and JSON-LD, so the visible page is identical by construction. Phase B changes rendering (SSR of /order, status codes, the client payload) and needs screenshot comparison. Phase C is content, data and Google-side work, much of it Dor's or the backoffice's.

**Tech Stack:** Next.js 15 App Router, React, Supabase, Vercel ISR, vitest, Playwright 1.60 (chromium installed).

**Spec:** the audit report (session scratchpad `seo-audits/myt/report.md`) and its summary in Claude memory `seo-audit-2026-11-07.md`. Finding numbers below (F1-F21) are the report's.

## Global Constraints

- Customer-facing: no visual or functional change unless the task says so and Dor saw before/after screenshots.
- Work on `main`. One local commit per task, by explicit path (`git commit -- <paths>`). Push only when Dor says "push"/"תדחוף".
- Before every commit: `npx tsc --noEmit` is clean (next.config ignores TS errors, so this is the real type gate) and `npx next build` passes (memory build-before-commit; don't run `yarn install`).
- Tests go in `lib/__tests__/<name>.test.ts` (vitest, `npx vitest run <file>`). Commit messages carry no AI co-author line (repo conventions).
- Never run `next dev` and `next build`/`next start` in this checkout at the same time.
- Brand name in titles: `מגה איבנטס` (not MYT / Mega Events / MegaEvents).
- Host: `https://www.mega-events.co.il`. Keep ISR (`revalidate = 3600`) and keep request-time APIs out of /order (2026-09-17 outage).
- A change to `lib/app.types.ts` needs the backoffice twin (`types/app.types.ts`), so say so.

## Review Focus

1. Removing the layout canonical: pages that never declared one must not end up with a wrong one. Homepage gets an explicit canonical, and `seo-check` asserts the canonical on every regression path.
2. /order SSR (T7): once the client bailout is gone, the server HTML must not say "הכרטיסים אזלו בינתיים" for a bookable event (memory order-page-ssr-soldout-placeholder).
3. Public event DTO (T11): every price a customer sees must be identical before and after. Assert it on the visible-text diff of `/`, the hubs and `/search`.
4. Sold-out and expired events: noindex, never a 500, and the customer still sees the existing sold-out screen.
5. Preview hosts (`*.vercel.app`): metadata built from `siteUrl` must keep working on previews.

## Verification Harness (used by every task)

- `scripts/seo-check.mjs` (Task 0), built on Node built-ins only:
  - `node scripts/seo-check.mjs snapshot <base> <out.json>` records, for each regression path: status, final URL, title, meta description, canonical, meta robots, x-robots-tag, JSON-LD `@type`s, H1 texts, img count, link count, and visible body text (scripts, styles and templates stripped).
  - `node scripts/seo-check.mjs diff <a.json> <b.json>` prints the fields that changed per path, plus a line diff of the visible text.
  - `node scripts/seo-check.mjs sitemap <base>` prints the URL count per section and the status of a sample of URLs.
- Regression paths: `/`, `/about`, `/faq`, `/terms`, `/privacy`, `/accessibility`, `/search?q=london`, `/c/football`, `/c/music`, `/c/destinations/london`, `/c/music/artists/coldplay`, `/artists/black-coffee`, `/order/999999`, plus two live /order ids picked from the sitemap at run time.
- Local server: `npx next build && npx next start -p 3100`. Stop it when done.
- Phase B adds `scripts/seo-shots.mjs`: Playwright screenshots of the regression paths at 1440x900 and 390x844 (before = production, after = localhost:3100) into `.seo-shots/` (gitignored).
